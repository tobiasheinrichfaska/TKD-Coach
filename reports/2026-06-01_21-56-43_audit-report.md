## Summary

**Counts:** Critical 1 (missing FEATURES_REQUIRED.md) · High 3 · Medium 6 · Low 7.

**Top 3 Critical/High fixes**
1. Make `AssessmentScreen`'s metric form **schema-driven** (`getMetricSchema` + `buildMetric`) so all 6 (and any user-added) metric types can be logged — 3 are currently impossible to enter.
2. Route `MetricRow` delta + `ProgressScreen` share through `fieldDelta`/`schema.primaryField` — fixes always-`0` progress share and "—" delta for 4 types.
3. Add `FEATURES_REQUIRED.md` defining the critical user paths so integration can be validated.

**Top 2 architectural improvements**
1. Honour the schema-driven assessment design end-to-end (domain layer is correct; the UI just doesn't call it) — retire the per-type `switch` blocks across the 3 assessment files.
2. Reuse `selectors`/`schedule` derivations in `DashboardScreen` instead of inlining status logic.

**Quick wins**
- Wrap `'HEUTE'` + run-timer strings in `t()` (+ `de.ts` keys).
- Remove `gameLogs` from the timer effect deps (perf; matches documented intent).
- Guard `combo_accuracy` division by zero; rename shadowing `t` params.

## Data-drivenity verdict

Separation is **mostly honored, with one significant breach.** The domain layer (`selectors`, `schedule`, `graduation`, `people`, `attendance`, `phases`, `metrics`, `migration`, `templates`) is genuinely UI-free (no React/RN imports), pure, and well unit-tested (113 tests / 13 suites); the session/groups/list screens render straight from it (`partitionPlans`, `reconcileRunningLogs` via `migrate`, etc.). The breach is the **assessment subsystem**: a fully realized data-driven metric model (`MetricTypeDef` + `buildMetric`/`fieldDelta`) exists and is tested, yet all three consumers (`AssessmentScreen`, `MetricRow`, `ProgressScreen`) ignore it and hardcode per-type branches — which is exactly why 3 metric types can't be logged and 4 produce wrong/empty progress. Plus minor business-logic leakage into the Dashboard. Fixing the assessment path would make "the logic layer runs without the UI; the UI only renders" true across the whole app.
